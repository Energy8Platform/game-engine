# Примеры игр - Простой раунд

## Пример 1: Слот-машина

**Подготовка состояния игры:**

- **reels** - результат барабанов в формате массивов символов
- **lines** - номера выигрышных линий
- **multiplier** - мультипликатор выигрыша
- **symbols** - подсчет символов для анализа
- **bonus_triggered** - флаг активации бонуса

**Структура запроса PlayRoundRequest:**

- Передать ID сессии `session_id`
- Передать множитель ставки в поле `price_multiplier`
- Указать индекс ставки через `bet_index`
- Отправить сумму выигрыша в поле `win_multiplier`
- Передать ID Фри Раунд Компании, если такая сейчас играется (опционально) `free_round_campaign_id`
- Включить активированные игровые функци `features`, если такие есть
- Включить версию стейта раунда `round_state_version`
- Включить состояние роунда `round_state` как JSON строку

**Обработка ответа:**

- Получить ID раунда из `round_id`
- Обновить баланс из `balance`
- Обновить состояние Фри Раунд Компании`free_round_campaign`, Фри Раунд Компания активна (не `null`)
- Сохранить результат игры для UI

## Пример 2: Рулетка

**Расчет выигрышей:**

- Суммировать все ставки для получения общей суммы
- Определить выигрышные ставки на основе выпавшего номера
- Рассчитать общую сумму выигрыша

**Состояние игры рулетки:**

- **winning_number** - выпавший номер (0-36)
- **bets** - массив всех ставок с типами и суммами
- **winning_bets** - массив выигрышных ставок
- **total_bet** - общая сумма всех ставок
- **total_win** - общая сумма выигрыша

**Особенности для рулетки:**

- `bet_index` обычно равен 0 (без уровней ставок)
- `price_multiplier` содержит множитель ставки
- Состояние включает детали всех типов ставок

## Пример 3: Лотерея

**Механика лотереи:**

- Генерировать номера игрока (например, 5 номеров из 42)
- Подсчитать совпадения с розыгрышными номерами
- Определить сумму выигрыша на основе количества совпадений

**Состояние игры лотереи:**

- **ticket_numbers** - выбранные игроком номера
- **drawn_numbers** - выпавшие в розыгрыше номера
- **matches** - количество совпадений
- **win_tier** - уровень выигрыша (tier_1, tier_2, etc.)
- **jackpot_won** - флаг выигрыша джекпота

**Параметры запроса:**

- `price_multiplier` равен множителю стоимости билета
- `bet_index` обычно 0 для лотереи
- `win_multiplier` рассчитывается по таблице выплат
- Джекпот определяется полным совпадением номеров

## Пример 4: Краш-игра

**Логика краш-игры:**

- Серверная генерация точки краха (crash point)
- Сравнение с автокешаутом игрока
- Выигрыш = ставка × мультипликатор (если кешаут успешен)

**Состояние краш-игры:**

- **crash_point** - точка краха (например, 2.45x)
- **auto_cashout_at** - мультипликатор автокешаута игрока
- **cashed_out** - успел ли игрок кешаутнуться
- **cashout_multiplier** - фактический мультипликатор выплаты
- **result** - результат: “win” или “crash”
- **game_duration_ms** - продолжительность раунда в миллисекундах

**Расчет выигрыша:**

- Если автокешаут ≤ точки краха: выигрыш = ставка × автокешаут
- Если автокешаут > точки краха: выигрыш = 0 (краш)

## Универсальный подход для простых игр

**Архитектура класса SimpleGameRound:**

**Конструктор:**

- Принимает тип игры и ID сессии
- Инициализирует базовые параметры для всех типов игр

**Основной метод play():**

1. Выполнение игровой логики через переданную функцию
2. Валидация результата игры
3. Создание состояния игры
4. Формирование и отправка PlayRoundRequest
5. Обработка ответа от API

**Создание состояния игры:**

- **Базовое состояние**: тип игры, временная метка, хеш результата
- **Слоты**: добавляет барабаны и линии
- **Рулетка**: добавляет номер и ставки
- **Лотерея**: добавляет розыгрышные и игровые номера
- **Другие игры**: универсальная структура данных

**Валидация результата:**

- Проверка корректности объекта результата
- Валидация суммы выигрыша (не отрицательная)
- Специфичные проверки по типу игры:

   - **Слоты**: наличие массива барабанов
   - **Рулетка**: корректность номера (0-36)
   - **Дополнительные проверки** для других типов игр

**Создание запроса:**

- Стандартная структура JRPC envelope
- Заполнение payload с игровыми данными
- Сериализация состояния игры в JSON
- Генерация уникальных ID и последовательности

> Совет
>
> Всегда генерируйте результаты игры на сервере. Никогда не доверяйте результатам, полученным с клиента!
