# Транзакционная модель

## Обзор

Транзакционная модель Artube Games API использует **иерархическую структуру** для обработки игрового процесса, ставок и выигрышей.

> Заметка
>
> Все транзакции привязаны к игровым раундам. Нет транзакций вне контекста раунда.

> Заметка
>
> Все игровые раунды привязаны к игровым сессиям. Нет раундов вне контекста сессии.

```plaintext
Session ──┐
          ├── Round 1 ── BET + WIN
          ├── Round 2 ── BET + WIN
          └── Round N ── BET + WIN
```

**Принцип:** Session `1:N` Round `1:1` BET + `1:1` WIN

## Основные принципы

### 🔄 Атомарность

Каждая транзакция выполняется полностью или откатывается целиком.

### 💰 Их всегда двое

- **BET (Дебет)** - списание средств с баланса игрока
- **WIN (Кредит)** - зачисление средств на баланс игрока

### 🤵 А он всегда Один

У одного игрока в один момент времени может быть только один активный раунд.

Попытка открыть новый раунд пока старый не закрыт приведёт к InvalidRoundOperation

### 🎯 Иерархическая привязка

Все транзакции связаны через: Session → Round → Transaction (BET + WIN)

## Сущности системы

| Сущность | Назначение | Ключевые атрибуты |
| --- | --- | --- |
| **Session** | Игровой контекст | `session_id`, `currency`, `balance` |
| **Round** | Игровое событие | `round_id`, `bet_index`, `win_multiplier`, `price_multiplier`, `round_state` |

## Операции системы

### 🎰 BET - Ставка

- Списание средств при начале раунда
- Нельзя отменить после подтверждения

### 🧮 Расчёт суммы ставки

Бекенд игры **не считает деньги**. Он передаёт всего два значения, а сумму BET вычисляет gamesapi:

- **`bet_index`** — индекс в массиве `allowed_bets` из [`SessionInfo`](../../games-api-integration/game-requests/session-info.md). Игра передаёт индекс, **а не** само значение ставки.
- **`price_multiplier`** — множитель поверх базовой ставки. Для обычного раунда равен **1**. Больше `1` он только когда игрок платит сверх ставки (например, покупка **Buy Feature**); для бесплатных/бонусных раундов равен `0`.

Сумма BET, которая попадает в транзакцию, всегда:

```plaintext
transaction_bet_amount = price_multiplier * allowed_bets[bet_index]
```

**Примеры** (`allowed_bets: [0.1, 0.5, 1, 2, 5]`):

| Сценарий | `bet_index` | `price_multiplier` | `allowed_bets[bet_index]` | Сумма BET |
| --- | --- | --- | --- | --- |
| Обычный раунд | 2 | 1 | 1 | `1 * 1 = 1` |
| Buy Feature (×3) | 2 | 3 | 1 | `3 * 1 = 3` |
| Бесплатный / бонусный раунд | 2 | 0 | 1 | `0 * 1 = 0` |

> Заметка
>
> Модель одинакова для простого **[PlayRound](../../games-api-integration/game-requests/play-round.md)** и для каждого запроса сложного раунда (**[OpenRound](../../games-api-integration/game-requests/open-round.md)** / **[UpdateRoundState](../../games-api-integration/game-requests/update-round-state.md)** / **[CloseRound](../../games-api-integration/game-requests/close-round.md)**). Держа расчёт на стороне gamesapi, мы гарантируем, что деньги всегда считаются одинаково, независимо от бекенда игры.

### 🏆 WIN - Выигрыш

- Зачисление выигрыша при завершении
- Может быть частичной (progressive wins)
- Мгновенное зачисление на баланс

### ↩️ ROLLBACK - Откат

- **Автоматически** при технических ошибках
- Полная отмена всех операций раунда
- Возврат средств в исходное состояние

> Осторожно
>
> Игра не может инициировать откат самостоятельно - только система.

### 🤖 AUTOCLOSE - Автозакрытие

- При таймауте сложного раунда
- “Наихудший исход” для игрока
- Автоматическое завершение раунда системой

> Заметка
>
> Подробности по автозакрытию в разделе [Autoclose](../../features/autoclose.md)

## Ограничения API

### ❌ НЕ поддерживается

| Ограничение | Причина |
| --- | --- |
| Множественные ставки в раунде | Один раунд = одна ставка |
| Прогрессивные ставки | Размер ставки фиксируется при создании |
| Отложенные выплаты | Все выплаты мгновенные |
| Условные выплаты | Логика решается до закрытия раунда |
| Частичные отмены | Операции атомарны и финальны |
| Кросс-раундовые транзакции | Каждый раунд финансово независим |

### ✅ Поддерживается

- Атомарная модель “ставка-результат”
- Последовательные раунды для сложных игр
- Множественные WIN в сложном раунде через UpdateRoundState
- Коллекты в крашах как отдельные раунды (как в Chicken Road)

## Правила консистентности

1. Валюта фиксирована на уровне сессии
2. Доступный набор ставок фиксирован на уровне сессии
3. Каждый раунд создает ровно одну пару BET+WIN транзакций
4. Последовательность номеров раундов не нарушается

## Обработка ошибок

### Критические ошибки

| Ошибка | Действие |
| --- | --- |
| `InsufficientFunds` | Проверить баланс через [`SessionInfo`](../../games-api-integration/game-requests/session-info.md) |
| `SessionIsNotInitialized` | Проиницилизировать сессию вызовом [`SessionInfo`](../../games-api-integration/game-requests/session-info.md) |
