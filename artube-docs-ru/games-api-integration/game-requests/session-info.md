# SessionInfo

## Обзор

Запрос `SessionInfo` используется для получения актуальной информации о сессии игрока, включая баланс, настройки игры, историю последних раундов и активные кампании бонусных раундов.

### Общее определение

Cессия (Session) — это фундаментальная единица учета активности игрока. Она представляет собой непрерывный период времени, в течение которого пользователь взаимодействует с конкретной игрой. Сессия представляет собой связку игра–игрок–валюта. Она инициируется игроком через казино и существует, пока игрок находится в игре. У игрока может быть несколько активных сессий одновременно. Однако для одной связки игра–игрок–валюта может существовать только одна активная сессия. При открытии новой сессии ранее существующая сессия автоматически закрывается, а вместо неё создаётся новая.

С точки зрения архитектуры, Сессия является агрегирующей сущностью. Она объединяет все действия игрока в единый логический контейнер, позволяя отслеживать финансовые показатели, поведение пользователя и техническое состояние игры от момента входа до выхода.

### Иерархия данных

Сессия является верхним уровнем трехуровневой вложенности данных. Для корректной интерпретации событий в системе используется следующая структура:

Session (Сессия) — родительский контейнер. Содержит общую информацию (кто играет, во что, итог по деньгам). Round (Раунд) — игровой цикл внутри сессии (например, один спин в слоте или одна раздача в картах). Сессия состоит из набора раундов. Transaction (Транзакция) — элементарная финансовая операция внутри раунда (Bet, Win, Rollback). Важно: Связь осуществляется через уникальный идентификатор — Session ID. Именно этот ключ используется для сквозного поиска событий во всех внутренних и внешних приложениях

### Жизненный цикл сессии

Каждая сессия проходит через определенные этапы, фиксируемые в системе статусами:

1. **Инициализация** - Сессия создается в момент запуска игры пользователем. Ей присваивается статус Active. В этом состоянии поля времени завершения (End Time) остаются пустыми.
2. **Активность** - В рамках активной сессии игрок совершает игровые раунды. Система в реальном времени обновляет агрегированные показатели (Total Bet, Total Win).
3. **Завершение** - Сессия переходит в статус Closed (Inactive), когда игрок покидает игру или срабатывает тайм-аут активности. Фиксируется финальное время (End Time) и итоговый расчет RTP.

В документации и интерфейсах сессия характеризуется следующим набором параметров:

Идентификаторы: Session ID — уникальный GUID сессии. Security Hash — уникальный хеш, используемый для идентификации игрока.

Финансовые метрики: Balance — текущий баланс игрока после всех транзакций. Currency — валюта, в которой происходила игра.

> Заметка
>
> В редких случаях (разрыв соединения, отложенные бонусные игры) может возникнуть ситуация «Разорванного раунда». В этом сценарии один игровой раунд может технически относиться к двум разным сессиям:
>
> Bet Session ID: Сессия, в которой была сделана ставка.
>
> Win Session ID: Новая сессия, в которой был начислен выигрыш после восстановления связи.

```
  "player_connection_info": {
    "ip_address": "192.168.1.100",
    "user_agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36",
    "player_connection_id": "abcdef12-3456-7890-abcd-ef1234567890"
  }
}
```

### Поля запроса

| Поле | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| `session_id` | string | обязательное | Идентификатор сессии (GUID формат) |
| `player_connection_info` | object | обязательное | Информация о подключении игрока |

#### PlayerConnectionInfo

| Поле | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| `ip_address` | string | опциональное | IP-адрес игрока |
| `user_agent` | string | опциональное | User-Agent браузера |
| `player_connection_id` | string | опциональное | Идентификатор подключения игрока между клиентом и бэкендом игры |

#### Валидация SessionInfoRequest

**Проверки обязательных полей:**

- `session_id`: Не должен быть пустым GUID

**Валидация player_connection_info:**

- `ip_address`: Если указан, должен быть валидным IPv4 или IPv6 адресом

**Примечание:**

- Страна игрока определяется автоматически на сервере через GeoIP сервис по IP-адресу

#### Что такое `allowed_bets` (модель ставок)

`allowed_bets` — это **массив допустимых ставок** для игры. Это множество задаётся **Account Manager’ом (AM)** в backoffice и фиксируется на уровне сессии — он определяет все размеры ставок, которые игрок может сделать в этой игре.

Ключевая идея: во время геймплея бекенд игры **никогда не передаёт саму сумму ставки**. Вместо этого он передаёт **`bet_index`** — индекс элемента в массиве `allowed_bets`. Например, при `allowed_bets: [0.10, 0.50, 1.00, 2.00, 5.00]` значение `bet_index: 2` означает ставку `1.00`.

Благодаря этому **все реальные денежные и математические расчёты выполняются исключительно на стороне gamesapi** — бекенд игры не считает деньги. Даже когда игрок платит сверх базовой ставки (например, покупка Buy Feature), бекенд игры всё равно не вычисляет сумму: он присылает **`price_multiplier`**. Для обычного раунда без покупки `price_multiplier` равен **1**.

Итоговая сумма ставки всегда:

```plaintext
transaction_bet_amount = price_multiplier * allowed_bets[bet_index]
```

> Заметка
>
> Это каноническая модель ставок, общая для обоих типов раундов — простого **[PlayRound](play-round.md)** и сложного раунда (**[OpenRound](open-round.md)** / **[UpdateRoundState](update-round-state.md)** / **[CloseRound](close-round.md)**). Полная формула, случай Buy Feature и разобранные примеры описаны в **[Транзакционной модели](../../integration-process/games-api/transaction-model.md#%D1%80%D0%B0%D1%81%D1%87%D1%91%D1%82-%D1%81%D1%83%D0%BC%D0%BC%D1%8B-%D1%81%D1%82%D0%B0%D0%B2%D0%BA%D0%B8)**.

#### Объект rtp_options (элемент)

| Поле | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| `is_visible` | bool | обязательное | Отображать ли данный RTP-вариант в правилах игры |
| `rtp` | decimal | обязательное | Процент возврата (96.50 = 96.5%) |
| `game_mode` | string | обязательное | Режим игры (“normal”, “turbo”, “auto”) |
| `volatility` | string | опциональное | Волатильность (“low”, “medium”, “high”) |

> Осторожно
>
> Поле `rtp` в `rtp_options` читается игрой, но фактическое значение вычисляется и перезаписывается на сервере на основе RTP игры, настроенного в Back Office; `game_mode` в этом контексте всегда `"main"`. Для отображения игроку итогового значения RTP и управления его видимостью используйте объект `rtp_settings`.

#### Объект rtp_settings (RtpSettingsResponse)

| Поле | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| `is_visible` | bool | обязательное | Необходимость отображения значения RTP игроку в правилах игры |
| `shown_rtp` | decimal | опциональное | Отображаемое значение RTP (96.50 = 96.5%), если `is_visible: true` |

| `base_currency_value` | decimal | обязательное | Максимальный выигрыш в базовой валюте |
| `player_currency_value` | decimal | обязательное | Максимальный выигрыш в валюте игрока |
