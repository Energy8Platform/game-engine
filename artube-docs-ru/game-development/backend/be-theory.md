# BE теория

## Игровой Сервер = Калькулятор

Ваш игровой сервер должен работать как простой калькулятор. Не как база данных, не как работающий со сложными состояниями микросервис, а как **примитивный калькулятор**:

- Получил входные данные → посчитал → вернул результат → **забыл всё**
- Никакой памяти между запросами
- Никаких сохраненных состояний
- Только чистая математика

**Всю память хранит Artube Games API через `round_state`**. Это их работа, не ваша.

Почему? Ну…

1. Сервер может упасть/перезапуститься в любой момент, и ничего не потеряется
2. Можно запустить 10 копий сервера, и они все будут работать одинаково
3. Легко воспроизвести любую проблему с теми же входными данными
4. Не нужно беспокоиться о синхронизации состояния, кэшах, сессиях и проч.

### Как это работает на практике?

При каждом запросе с клиента игры нужно сделать следующее:

1. Достать текущее состояние из Artube Games API
2. Посчитать новое состояние (чистая математика)
3. Сохранить обратно в Artube Games API
4. Вернуть результат игроку

Между запросами сервер вообще не знает, что происходит в игре. И это **хорошо**.
