# Backend Integration Free Round Campaign (FRC)

## Введение

Интеграция Free Round Campaign на стороне игрового бэкэнда минимальна, так как основная логика управления кампаниями лежит на стороне Games API. Однако, клиенту необходимо учитывать ряд особенностей при работе с API и, возможно, делать дополнительные проверки для отдельных кейсов, чтобы фронтенд корректно отображал специфичные ошибки.

### Обновление данных

Данные о кампании должны обновляться автоматически:

- В ответе на каждый спин
- В ответе на запрос сессии при переподключении

## Структура данных

Объект `FreeRoundCampaign`, получаемый от сервера:

```json
{
  "campaign_id": "uuid-string",
  "bet": 10.0,
  "currency": "EUR",
  "rounds_total": 50,
  "rounds_left": 50,
  "total_win": 0.0,
  "valid_from": "2023-10-27T10:00:00Z",
  "valid_to": "2023-10-28T10:00:00Z",
  "is_complete": false
}
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `campaign_id` | `string` | Уникальный идентификатор кампании (UUID) |
| `bet` | `number` | Ставка, на которой будут проводиться бесплатные раунды |
| `rounds_total` | `number` | Сколько всего раундов предоставлено |
| `rounds_left` | `number` | Сколько раундов осталось отыграть |
| `total_win` | `number` | Сумма выигрышей за все сыгранные раунды кампании |
| `valid_from` | `string` | Начало периода, когда кампанию можно активировать |
| `valid_to` | `string` | Конец периода, после которого кампания сгорает (ISO 8601, UTC) |
| `is_complete` | `boolean` | `true`, когда все раунды отыграны или кампания отменена |

> Осторожно
>
> Поле `freeRoundCampaign` может быть `null` - это означает отсутствие доступных кампаний. Если есть доступная кампания, то логика по активации кампании (предложение пользователю отыграть раунды за счёт FRC) должна быть реализована на стороне бэкенда самой игры. При переподключениях пользователь снова должен иметь возможность повторно активировать кампанию либо отказаться и играть в обычном режиме.

### Логика активации кампании

1. **Анонсер (Announcer)** Получение подтверждения активации кампании от игрока.
2. **Сохранение выбора на стороне бэкенда игры в активной сессии**
3. **Дополнительная валидация на стороне бэкенда игры**

   - Не поменялась ли ставка в запросе, так как это не валидное состояние
   - Повторный вызов активации Кампании в текущем соединении
   - Попытка активации несуществующей FRC, т.е не той, которая была в ответе на сессию от Games API
   - Попытка сделать покупку фичи в рамках FRC, так как они не разрешены
   - Прочие возможные ошибки на стороне бэкенда игры
4. **Передача активной `freeRoundCampaignId`** Бекенд игры должен передавать `freeRoundCampaignId` в запросах **[PlayRound](../../games-api-integration/game-requests/play-round.md)** и **[OpenRound](../../games-api-integration/game-requests/open-round.md)**
5. **Актуализация ответов** Спины проходят как обычно. В ответах **[PlayRound](../../games-api-integration/game-requests/play-round.md)** и **[CloseRound](../../games-api-integration/game-requests/close-round.md)** обновляются счетчики `roundsLeft` и `totalWin`.
6. **Завершение** Когда `roundsLeft` достигает 0:

   - Показывается попап с итоговым выигрышем (`totalWin`).
   - Интерфейс разблокируется, возвращаясь к дефолтной ставке игрока.

> Совет
>
> Актуально, если поле `freeRoundCampaign` не `null` в ответе на запрос сессии.

## Ошибки в ответе от Games API

| Код | Описание | Действие |
| --- | --- | --- |
| `FrcNotFound` | FRC не найдена | Исправить запрос |
| `FrcAlreadyCompleted` | FRC завершена | Исправить запрос |

### FrcNotFound

```json
{
  "code": "FrcNotFound",
  "message": "Для данной сессии такой кампании нет.",
  "details": {}
}
```

### FrcAlreadyCompleted

```json
{
  "code": "FrcAlreadyCompleted",
  "message": "Campaign was already completed.",
  "details": {}
}
```
