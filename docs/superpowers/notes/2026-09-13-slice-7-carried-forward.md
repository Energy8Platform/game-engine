# Срез 7 «оболочка по образцу VS Code» — что осталось после

Ветка `feat/slot-webide-cordis`, коммиты `a3b3b65..c6cd445` (22 штуки).
План: `docs/superpowers/plans/2026-09-11-the-shell-after-vscode.md`.
Спека: `docs/superpowers/specs/2026-09-11-vscode-shell-design.md`.

## Что срез сделал

IDE разложена как VS Code: activity bar, sidebar, группа вкладок-документов,
нижняя панель, статус-бар — и каждая область есть именованный слот на
существующем `ctx.slots`. Два экрана над одним деревом стали одним
Проводником, открывающим файлы вкладками. Состав и Превью — документы.
Каждый открытый документ остаётся смонтированным, скрытый — спрятан; текст,
курсор и история правок переживают переключение. Активный документ живёт в
хеше; глубокая ссылка на документ плагина ждёт, пока плагин догрузится, и
«не зарегистрирован» звучит только после того, как загрузчик отчитался.
Плагин открывает файл в отгруженном редакторе через `ctx.shell.openPath`.
`DESIGN.md` и `styles.css` переписаны под плоские токены, две темы.

Долг Среза 6 п. 2 (ложное «не зарегистрирован» при загрузке) погашен — и для
встроенных экранов, и для плагинов. Долг Среза 6 п. 3 (Back/Forward мимо
стража) погашен побочно: смонтированным документам терять нечего.

## Остаток долга

1. **Вклад `shell.document`, отозванный при открытой вкладке**, оставляет
   незакрываемую вкладку с размонтированным компонентом — `onSlotsChange`
   следит только за `pending`. Класс пустой области; первым решением
   следующего среза.
2. **Компоненты получают корневой `ctx`.** `e8.client.inject` ограничивает
   `apply`, но не то, до чего дотянется отрисованный компонент. Плагин
   первоклассный по утечке, а не по устройству. Существовало до среза.
3. **Загрузка только в корень**, без меню по каталогу — §5 спеки сужена без
   решения. Записано здесь как решение задним числом.
4. **`SessionStatus` показывает ● после первого кадра и не возвращается к ○**
   после смерти процесса. `ProjectStatus` показывает id строки плагина —
   имени проекта на проводе нет; это забота среза управления проектами.
5. **`Cmd+S` на не-редакторской вкладке** открывает диалог браузера —
   `preventDefault` только у редактора. `beforeunload` без `returnValue = ''`
   для Safari.
6. Из прежних срезов без изменений: жёсткая ссылка наружу, `node_modules`
   доступен на запись, base64, дерево целиком, отзыв у общего списка,
   `PAGE_NEEDS`, голый `ctx.layout.screen` — теперь голый
   `ctx.slots.register` из плагина без `ctx.effect` — течёт так же.

## Метод: что подтвердилось, и дороже всего

**Тест, регистрирующий вклад ДО монтирования, не видит компонент, который
не подписан на реестр.** `<Shell/>` прошёл проверку задачи 2 без подписки на
`ctx.slots`: каждый тест регистрировал до `render`, каждое изменение после
шло через `ctx.shell`, который слушается. Поздний вклад плагина не рисовался
вовсе, и нашёл это перенесённый тест из удаляемого `layout.test.tsx`.
Компоненту, рисующему реестр, нужен один тест, регистрирующий после
монтирования.

**jsdom не знает геометрии.** Подтверждение закрытия грязной вкладки было
нарисовано под панелью — оба `position`, оба `z-index: auto`, порядок в DOM
решал — и кнопка «Нет» была некликабельна ни для кого. Шесть задач юнит-тестов
и браузерная проверка задачи 6 это пропустили: `fireEvent.click` по testid
«попадает» всегда. Нашёл только клик Playwright по пикселю. На UI-срезе
Playwright не факультатив.

**Хеш как единственная истина — и `push` против `replace`.** Значение по
умолчанию и откат при опечатке писали хеш присваиванием, то есть проталкивали
запись в историю: один Back от свежей загрузки давал пустой хеш и пустой
экран, а откат по опечатке зацикливал Back навсегда — с одной строкой в
панели, потому что дубли схлопываются по тождеству. Выбор оболочки — не место,
куда человек ходил; он пишется `replace`. И `close()` тоже: `push` оставлял
Back на только что закрытой вкладке.

**Правило «удаления после последнего пользователя» поймано сканированием.**
План удалял `layout.tsx` в задаче 1, `Layout.tsx` в задаче 2, экраны в
задаче 5 — при `App.tsx`, использующем всё это до задачи 6. Дерево не
собиралось бы между задачами. Ничего не удаляется до миграции.

**Мутация должна сравниваться с базой, а не читать ноль.** Дважды за срез
`grep -c` вернул 0 по шаблону, которого в файле никогда не было (`options?.`
против `opts?.`, `.sort(byOrder)` против `byOrder(...)`), и это читалось как
«приземлилась». Счёт до/после на оригинале — единственное, что отличает.

**Рассылка, оборванная на полуслове, даёт правдоподобный результат.** Дважды.
Реализатор делал код и тесты и останавливался перед мутациями, отчётом и
коммитом; рецензент читал файл находок и справлялся. Обрыв не виден по
результату — только по тому, чего в нём нет.

**Тридцать пять холостых утверждений на ветке к концу среза.** Из этого среза
— шесть, все из моего текста плана: фикстура с одним файлом, сосед-тест,
несущий чужую половину, контейнер, посчитанный кнопкой регулярным выражением,
`hashchange`, удаляемый при всех зелёных.
