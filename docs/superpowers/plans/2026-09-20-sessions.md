# Sessions and the Spec Prelude Implementation Plan (slice 23)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A round plays to completion from the flow (`step`), the CLI measures complete rounds, and a `GameSpec`-shaped `spec.json` gets its prelude prepended by the host — so free spins, bonus rounds and spec-driven maths reach the IDE.

**Architecture:** `SpinRequest.roundId` routes `session-dev.play` to gRPC `Step`; the preview route forwards it; a `step` flow kind posts it with `$result` defaults; `compute/spin` loops `Step` until `roundComplete`. A host `spec` plugin assembles `buildSpinScript(defineGame(spec), logic)` into `<project>/.e8/game/script.spin` and switches the games dir for such projects; `schema`/`check` read the assembled file.

**Tech Stack:** cordis 4.0.0-rc.8, `@grpc/grpc-js` (session-dev), `@energy8platform/platform-core/game-spec` (`defineGame`, `buildSpinScript`, `validateSpec`), schemastery, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-20-sessions-design.md`

## Global Constraints

- `SpinRequest.roundId?: string` → `play` calls gRPC `Step({ round_id, action, params_json, request_id })`; the answer maps to `SpinResult` with `roundId = req.roundId`; errors keep the `[session-dev] e8-server: …` throw. The route forwards `body.roundId`.
- `step` kind: `roundId` default `'$result.roundId'`, `action` default `'$result.nextActions.0'`, `betLevel` as `spin`; unresolved `roundId`/`action` → `report` + `{ out: 'failed' }`; else POST `{ roundId, action, betLevel }` → `{ out: 'result', vars: { result, request } }`; `outs: ['result','failed']`. `readPath` follows numeric segments into arrays.
- Example ≡ template `flow.yml`: `done` (`if`, `when: $result.roundComplete`) after `draw`; `true → idle`, `false → step → draw`; `ui` positions keep the row layout (`draw` 940, `done` 1120, `step` 1120/240).
- `e8 spin`: `Step` with `nextActions[0]` until `roundComplete` (cap 500 → diagnostic `round did not complete in 500 steps`); `rtp`/`wins`/`maxWin` over the round's final `totalWin`; report gains `steps`; the first-response warning goes.
- Host `spec` plugin: a `GameSpec` (`type === 'slot'` and `symbols[0].pays`) → `.e8/game/script.spin` = `buildSpinScript(defineGame(spec), game/script.spin)`; `gamesDir` = `.e8/game`; `validateSpec`/`defineGame` failures → diagnostics `spec` / `game/spec.json`, no game; re-assemble on writes to `game/spec.json` and `game/script.spin` before the restart; `schema` + `compute/check` read the assembled file when present; a descriptive `spec.json` changes nothing. Template `.gitignore` gains `.e8/`.
- `first-slot` ≡ `slot-basic` on the pinned files (`flow.yml` changes in both, byte-identical; `.gitignore` is new in both).
- Never stage `packages/*`, `engine/apps/web/dist`, `engine/examples/first-slot/concept.png`, nor the user's untracked `docs/superpowers/notes/2026-09-19-paper-duel-port-feasibility.md`; the root lockfile is gitignored; no `git checkout`/`git stash` on files you did not create; never kill a process you did not start (the user's `e8 dev`, pid 79460, holds 5681/5682/24678 — expected); Playwright runs ALONE (one file per task; the full run is the controller's).
