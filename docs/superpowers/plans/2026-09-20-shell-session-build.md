# Shell, Session and Build Implementation Plan (slice 26)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `session` service behind the existing seam (the host's `/api/spin` or the Energy8 SDK), the Pixi shell as a row the flow drives and listens to, and `e8 build` producing a static `dist/` — so `first-slot` plays with real chrome and ships.

**Architecture:** `@energy8engine/contracts` gains `SessionService`; the flow's `spin`/`step` call it. Two rows (`session-host`, `session-sdk`) declare the `session` seam; `createGame` already picks one per `buildTarget`. `shell-pixi` wraps `createPixiShell`, re-emits `ShellEvents` as `shell.<name>` on the flow bus and registers a live `$shell` root; a `shell` flow kind calls the setters. `e8 build` boots a host, freezes its `GET /api/*` answers into `dist/api/*`, and bundles the page with a vite plugin that maps row ids to their runtime entries.

**Tech Stack:** cordis 4, schemastery, `@energy8platform/shell/pixi` (built dist), `@energy8platform/platform-core` (`createPlatformSession`, `DevBridge`), `@energy8platform/game-sdk` (`devMode` memory channel), vite 5 (build API), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-20-shell-session-build-design.md`
