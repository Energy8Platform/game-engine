# Оболочка IDE по образцу VS Code — дизайн

Дата: 2026-09-11. Ветка `feat/slot-webide-cordis`, от `7beed0d`.
Родительская спека: `2026-08-27-slot-webide-cordis-design.md` (§5 клиентские
сервисы и экраны; §8 один список; Приложение Б — что берём у deepseek-harness).

## 1. Зачем

Шесть срезов дали IDE четыре экрана, выстроенных вкладками поверх одного
контейнера. Они работают и проверены, и ими неудобно пользоваться:

- «Ассеты» и «Код» — два экрана про одно дерево файлов, с разными списками и
  разными действиями. Человек, привыкший к редактору, ищет один проводник.
- Экран — единственная единица навигации. Нет места, где живёт «текущий
  проект», нет статуса `e8-server`, нет постоянной боковой области. Каждая
  новая способность становится ещё одной вкладкой в верхней строке.
- Стиль взят с маркетингового сайта (Cal.com в `DESIGN.md`): мягкие карточки,
  крупные отступы. Это не инструмент разработки.

Целевой образ — VS Code: activity bar, sidebar, группа редакторов-вкладок,
нижняя панель, статус-бар. Не потому, что это модно, а потому, что у каждой
из этих областей есть **ясное назначение**, которое человек уже знает, и
потому, что раскладка выдерживает рост: новая способность — это кнопка и
вид, а не ещё одна вкладка сверху.

Из Приложения Б родительской спеки берётся главное: **именованные слоты как
единственная точка входа в UI**. Каждая область оболочки — слот. Плагин
проекта приносит кнопку в activity bar и вид в sidebar тем же путём, каким
сейчас приносит экран. Это не меняется; меняется то, куда вклад ложится.

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Порядок | Оболочка раньше управления проектами | Список проектов живёт в новой оболочке; иначе экран Воркспейса переделывается дважды |
| Образец | Анатомия классического VS Code + плоская современная палитра | ModernUI 1.136 не измерен; анатомия известна точно, палитра — токены, которые поправить дёшево |
| Ассеты + Код | Один Explorer в sidebar; файл открывается вкладкой-документом | Одно дерево, один вызов `tree()`, один набор действий |
| Состав, Превью | Документы в группе редакторов, кнопки в activity bar | Форма и стена — «документы», у них есть содержимое; не переделываем их внутренность |
| Диагностика | Нижняя панель, всегда видна | Уже хром с Среза 5; §8 держится |
| Темы | Тёмная и светлая через токены | Цена — один набор переменных; светлая нужна для скриншотов в документации |
| Что вне | Управление проектами, Воркспейс, горячий форк, split-view, поиск, git | Следующие срезы; этот — оболочка и переезд в неё |

## 3. Анатомия

```
┌──┬───────────┬────────────────────────────────┐
│  │           │ ◦ script.spin  ◦ Состав  × ... │  ← вкладки-документы
│AB│  sidebar  ├────────────────────────────────┤
│  │           │                                │
│  │           │        активный документ       │
│  │           │                                │
│  │           ├────────────────────────────────┤
│  │           │ panel: Диагностика (3)         │
├──┴───────────┴────────────────────────────────┤
│ status bar: first-slot · e8-server ● · ● dirty │
└───────────────────────────────────────────────┘
```

Пять областей и их размеры по умолчанию: activity bar 48px; sidebar 260px,
сворачивается кликом по активной кнопке; группа редакторов — остаток; panel
200px, сворачивается; status bar 22px. Sidebar и panel тянутся мышью; ширины
сохраняются в `localStorage` на этот браузер — удобство, не состояние.

## 4. Сервис `shell` и пять слотов

`layout` переименовывается в `shell`. `screen()` уходит. Пять слотов, все
через существующий `ctx.slots`, чтобы политика столкновений, диспозеры и
диагностика столкновений остались там, где они уже проверены:

| Слот | Вклад | Кто рисует |
|---|---|---|
| `shell.activity` | `{ key, title, icon, order, opens: 'sidebar' \| 'document' }` | activity bar |
| `shell.sidebar` | `{ key, title, component }` | sidebar, один активный |
| `shell.document` | `{ key, title, component, closable }` | группа редакторов, вкладка |
| `shell.panel` | `{ key, title, component }` | нижняя панель, вкладки |
| `shell.status` | `{ key, side: 'left' \| 'right', order, component }` | статус-бар |

Кнопка activity bar с `opens: 'sidebar'` показывает вид `shell.sidebar` с тем
же `key`; с `opens: 'document'` — открывает документ `shell.document` с тем
же `key`, один экземпляр (повторный клик — активирует).

`shell` держит: какой sidebar активен, какие документы открыты и какой
активен, свёрнута ли panel. **Активный документ живёт в хеше адреса**, как
сейчас экран: `#/doc/<key>`. Глубокая ссылка и перезагрузка работают так же.

Документы, открытые из Explorer, — не вклады, а экземпляры: `shell.open(key,
title, component)` кладёт вкладку без регистрации в слоте. Грязное состояние
— свойство вкладки: `shell.markDirty(key, boolean)`; вкладка с точкой не
закрывается без подтверждения, и `beforeunload` держит страницу.

Страж ухода из Среза 6 переезжает: вместо «страж на `go()`» — «страж на
закрытии вкладки и на смене активного документа», и `beforeunload` как был.

## 5. Explorer

Один вид `shell.sidebar` с `key: 'explorer'`, кнопка `shell.activity` с тем
же ключом, первая в порядке. Дерево — `ctx.files.tree()`, один вызов,
каталоги раскрываются. Клик по файлу открывает документ:

| Файл | Документ |
|---|---|
| `.spin`, `.ts`, `.js`, `.json`, `.yml`, `.md`, `.html`, `.css` | Monaco; для `.spin` — проверка и маркеры как в Срезе 6 |
| `.png`, `.jpg`, `.gif`, `.svg`, `.webp` | просмотр картинки через `urlFor` |
| всё, что `looksBinary` | «не показан, и почему» |
| больше порога | «не показан, и почему» |

Контекстное меню записи: **загрузить сюда** (для каталога), **удалить** (для
файла, с подтверждением). Загрузка обновляет дерево после ответа хоста, не
до — правило Среза 5 держится.

`AssetsScreen` и `CodeScreen` удаляются. Их логика — проверка с debounce и
стражем устаревшего ответа, сниф двоичного, порог размера, страж грязного,
доклад отказа в общий список — переезжает в документ-редактор и документ-
просмотр. Ни одно правило не теряется; тесты, которые их закрепляют,
переезжают вместе с ними.

## 6. Судьба экранов

| Было | Становится |
|---|---|
| вкладка «Состав» | кнопка `shell.activity` `composition`, документ `shell.document` `composition`; внутренность `CompositionScreen` без изменений |
| вкладка «Превью» | кнопка `preview`, документ `preview`; `PreviewWall` без изменений |
| вкладка «Ассеты» | Explorer + документ-просмотр |
| вкладка «Код» | Explorer + документ-редактор |
| панель диагностик в хроме | `shell.panel` `diagnostics`, единственная вкладка панели сегодня |
| `screen-demo` плагин | приносит кнопку `demo` и документ `demo`; доказывает открытость **обоих** слотов |
| — | `shell.status`: имя проекта (слева), состояние `e8-server` (справа), грязные документы (справа) |

Порядок в activity bar: Explorer, Состав, Превью, затем вклады плагинов по
`order`.

## 7. `DESIGN.md` и токены

`DESIGN.md` переписывается. Источник — анатомия VS Code и его тёмная тема по
умолчанию, без притязаний на конкретную версию. Принципы:

- Плоские поверхности. Ни теней, ни градиентов, ни скруглений больше 4px.
- Четыре уровня фона: `--e8-bg-0` (editor) … `--e8-bg-3` (activity bar) и
  одна линия-разделитель `--e8-border`.
- Одна акцентная `--e8-accent` для активного элемента и фокуса.
- Текст: `--e8-fg`, `--e8-fg-muted`; шрифт системный (`-apple-system, Segoe
  UI, …`), 13px база, 12px в статус-баре; моноширинный для редактора.
- Тёмная тема по умолчанию; светлая — тот же набор токенов под
  `[data-theme="light"]`; переключатель — элемент `shell.status`.
- Все размеры областей (§3) — токены.

`styles.css` переписывается под токены; классы `e8-*` остаются как есть там,
где не меняется смысл.

## 8. Отказ — это данные, применительно к оболочке

- Ноль вкладов в `shell.activity` → activity bar пуст, sidebar показывает
  «ничего не зарегистрировано» с диагностикой, а не пустоту.
- Документ, чей компонент бросил, — граница ошибки на вкладке; остальные
  вкладки и panel живы. То же правило, что у экрана в Срезе 4.
- Хеш, называющий документ, которого нет, — диагностика и первый документ.
  **Долг Среза 6, пункт 2** — ложное предупреждение при загрузке, потому что
  `current()` докладывал между эффектами регистрации, — гасится здесь:
  `shell` откладывает проверку хеша до конца первого рендера.
- Вклад в слот с неизвестным `opens` — диагностика столкновения слотов, как
  сейчас.

## 9. Что не входит

Управление проектами и один процесс `e8` с N проектами (следующий срез,
получит первую кнопку activity bar). Воркспейс. Горячий форк. Split-view и
перетаскивание вкладок. Поиск по проекту. Git. Палитра команд. Клавиатурные
сочетания кроме `Ctrl/Cmd+S`.

## 10. Проверка

- Все существующие Playwright-тесты проходят. `data-testid` переезжают:
  `tab-<id>` → `activity-<key>` и `doc-<key>`; `entry-<path>` и
  `file-<path>` → `explorer-<path>`; `editor`, `diagnostics-panel`,
  `confirm-yes`, `tile-*`, `row-*`, `diag-*` — как были.
- Приёмка среза, через живой хост и настоящий браузер:
  1. чужой плагин приносит кнопку и документ, и оба видны — открытость
     обоих слотов;
  2. Explorer открывает `.spin` редактором, PNG просмотром, двоичный —
     объяснением;
  3. грязная вкладка не закрывается без подтверждения; `beforeunload` держит;
  4. загрузка на `#/doc/preview` открывает превью **без** ложного
     предупреждения — долг Среза 6 погашен;
  5. документ, который бросил, не роняет panel и другие вкладки;
  6. IDE загружается с Monaco внутри, консоль без ошибок — как в Срезе 6.
- Юнит-тесты слотов, `shell`, стража грязного, Explorer — как в прежних
  срезах: каждое утверждение с мутацией, которая обязана его уронить.

## 11. Риски

| Риск | Вес | Что делаем |
|---|---|---|
| Переезд двух экранов в документы потеряет правило, закреплённое тестом | высокий | Тесты `code-screen`/`assets-screen` не удаляются, а переносятся; удалять тест — только с вопросом «список или свойство» из записки Среза 5 |
| Тестовая сюита Playwright сломается о переехавшие testid | средний | Таблица переезда в §10; приёмка Среза 6 (Monaco в браузере) остаётся неизменной |
| Хеш-навигация по документам разойдётся с состоянием вкладок | средний | Хеш — единственный источник истины для активного документа, как для экрана сейчас; открытые вкладки — состояние `shell`, восстанавливаются из `localStorage` как удобство |
| Стилизация уведёт в переделку внутренностей экранов | средний | §6 явно: `CompositionScreen` и `PreviewWall` без изменений внутри; меняется контейнер |
