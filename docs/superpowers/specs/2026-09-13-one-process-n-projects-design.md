# Один процесс, N проектов — дизайн

Дата: 2026-09-13. Ветка `feat/slot-webide-cordis`, от `7496550`.
Родительская спека: `2026-08-27-slot-webide-cordis-design.md` — §5 (сервис
`workspace`, экран «Воркспейс»), §6 (шов `workspace`/`project`: «проект
адресуется id, а не путём — с первого дня»; правило 2: превью на отдельном
origin). Оболочка: `2026-09-11-vscode-shell-design.md`, `2026-09-13-modern-ui-design.md`.

## 1. Зачем

Сегодня, чтобы работать над игрой, человек запускает два процесса в двух
папках: `e8 dev` в папке проекта (хост 5679 + vite игры + `e8-server`) и
`npm run dev` в `engine/apps/web` (оболочка IDE, 5680). Хост оболочку не
раздаёт; проект — это `cwd`, один и навсегда; списка проектов нет;
`ProjectStatus` показывает id первой строки композиции, потому что имени
проекта на проводе нет. Родительская спека §6 говорит, что переезд в облако
без сервиса `workspace` превращается в переписывание, а правило «превью на
отдельном origin» сегодня держится случайно — потому что 5679 ≠ 5680.

Цель среза: **одна команда `e8` — один процесс** — раздаёт IDE, показывает
проекты воркспейса, по клику поднимает игру выбранного проекта внутри
себя и переключает её при выборе другого. Игру отдельно не запускают.

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Откуда проекты | Папка-воркспейс: `e8` в её корне; каждая подпапка с `e8.yml` — проект; `id` = имя папки | Одно правило, работает на диске и на томе в облаке; id не путь |
| Сколько игр | Одна активная; переключение = dispose scope + plugin | Один `e8-server`, один порт превью, сервисы хоста не становятся per-project |
| `e8 dev` | Остаётся: `cwd` — проект → воркспейс из него одного, открыт сразу | Ничего из 70 e2e-тестов не переписывается: фикстура — папка-проект |
| Превью | Второй HTTP-сервер в scope `dev-game`, порт 5681 | Правило §6.2 держится нарочно; порт освобождается вместе со scope |
| Оболочка IDE | Хост раздаёт `engine/apps/web/dist` на 5679 `/` | Один процесс для пользователя; `npm run dev` (5680) остаётся для разработки самой IDE |
| Имя проекта | `game/spec.json`.`name`, иначе `id` — на провод | Долг среза 7 (`ProjectStatus` показывает id плагина) закрывается |
| Смена проекта при грязных вкладках | Клиент спрашивает до запроса; чужое переключение закрывает с диагностикой | Хост — источник истины об активном проекте; вкладки — состояние одного браузера |
| Что вне | Создание проекта из шаблона; несколько активных игр; песочница хостовых плагинов; identity; горячий форк | Следующие срезы |

## 3. Команда и процесс

```
e8            в папке-воркспейсе: список проектов, ничего не открыто
e8 dev        в папке проекта: воркспейс из одного проекта, он открыт
e8 ide        синоним e8
```

Правило одно: **если `cwd` содержит `e8.yml` — `cwd` и есть единственный
проект, и он открывается сразу; иначе проекты — подпапки `cwd` с `e8.yml`,
ни один не открыт.** `e8 dev` в папке без `e8.yml` — та же диагностика,
что сегодня у `e8 ide`: «в этой папке нет проектов», хост стартует.

Порты: 5679 — API, `/ide` ws, `/plugin-client`, оболочка IDE; 5681 —
превью активной игры (`/`, `/api/spin`, `/plugin-runtime`, `/@fs/`);
`e8-server` — эфемерный, как сейчас. `PORT` и `PREVIEW_PORT` из окружения
переопределяют (`0` — свободный), как сегодня `PORT`.

## 4. Сервис `workspace` (хост)

```ts
interface Project { id: string; name: string; }
interface WorkspaceState {
  projects: Project[];
  active: string | null;
  previewUrl: string | null;       // http://127.0.0.1:5681 пока активен проект
  diagnostics: Diagnostic[];       // сканирование папки, spec.json без name и т.п.
}
interface WorkspaceService {
  state(): WorkspaceState;
  open(id: string): Promise<Diagnostic[]>;   // [] — открыт; иначе почему нет
  close(): Promise<void>;
  rescan(): Promise<void>;
}
// событие: ctx.emit('workspace/changed', state)
```

Локальный провайдер: `readdir(root)`, проект — каталог с `e8.yml`
(символические ссылки не следуются — правило `files`). `name` из
`game/spec.json` (`name`, строка), иначе `id`; `spec.json` отсутствует или
без `name` — не диагностика, просто `id`. Путь проекта — внутреннее знание
провайдера; наружу только `id`. В облаке этот же интерфейс над томом.

`open(id)`: если `id` не в списке — диагностика `workspace`, ничего не
меняется. Если активен другой — сначала `close()`. Затем `ctx.plugin(
projectScope, { cwd })` (§5) и `await` его готовности; ошибка старта —
диагностика, `active` остаётся `null`, порт 5681 свободен. `close()`:
`fiber.dispose()` scope проекта; `session-dev` уже гасит `e8-server` при
dispose (срез 6). Вызовы `open`/`close` сериализуются одной цепочкой
промисов, как `SessionService.restart()`.

## 5. Область проекта

Сегодня `createIdeHost({ cwd })` регистрирует на корне: `Loader` +
`plugin-include` (`e8.yml` IDE-плагинов, относительно `ctx.baseUrl` = cwd),
`composition`, `project`, `schema`, `files`, `Server`, `rpc`,
`client-assets`, `runtime-assets`; `e8 dev` добавляет `dev-game`.

Становится: `createIdeHost({ root })` регистрирует **без проекта** `Loader`,
`Server` (5679), `rpc`, `workspace`, `ide-static` (§7). Всё, что читало
`cwd`, уезжает в один плагин `project-scope` (`plugins/project-scope.ts`),
который `workspace.open()` подключает с `{ cwd, previewPort }`: внутри него
`composition` (с `bootDiagnostics` от загрузки `e8.yml`), `project`,
`schema`, `files`, `client-assets`, `runtime-assets`, `dev-game`. Порядок
и `inject` — как сейчас в `createIdeHost`; меняется только владелец scope.

`e8.yml` IDE-плагинов проекта грузится **абсолютным** путём: `ctx.loader.
create({ name: '@cordisjs/plugin-include', config: { path: pathToFileURL(
join(cwd, 'e8.yml')).href } })` внутри `project-scope`, а запись — entry
id — хранится, чтобы `ctx.loader.remove(id)` на dispose. `ctx.baseUrl`
корня больше не указывает на проект. **Это измеряется первой задачей
плана** (spike): принимает ли `plugin-include` file-URL, снимается ли
entry вместе со scope, остаются ли строки в `ctx.loader.entries()` после
`remove`. Если не принимает — путь относительный от `root` (`./first-slot/
e8.yml`); если entry не снимается — `composition` держит фильтр по
префиксу пути и `rpc.snapshot()` показывает только строки активного
проекта. Ответ спайка входит в план как правило, не как надежда.

`rpc` живёт на корне (соединения переживают смену проекта); `snapshot()`
берётся у `ctx.composition`, которого на корне нет — `rpc` читает его
лениво через `ctx.get('composition')`, и при `null` шлёт пустой снимок
`{ rows: [], diagnostics: [] }`. `files/written` → `dev-game` — оба внутри
scope, связь как была.

## 6. Превью на своём origin

`dev-game` вместо `ctx.server.all(/^.*$/)` на 5679 поднимает в своём scope
`ctx.plugin(Server, { host, port: previewPort })` — второй экземпляр
`@cordisjs/plugin-server` — и вешает на него vite-игру, `/api/spin`,
`/@fs/` и `/plugin-runtime` (переезжает из `runtime-assets` вместе с игрой:
единственный потребитель — игра). Диагностики `/api/spin` по-прежнему идут
в `ideRpc` корня (`inject: ['ideRpc']`). Ошибка bind 5681 — диагностика
`dev-game`, проект открыт без превью, `previewUrl: null`.

Клиент: `PreviewWall.computePreviewUrl()` (`:5679` жёстко) заменяется
чтением `previewUrl` из `WorkspaceState`; `null` → «превью недоступно» с
диагностикой, не пустой iframe. Правило §6.2 записывается в `dev-game`
как рабочая инвариантность, а не как «случайно держится».

## 7. Оболочка IDE с хоста

Плагин `ide-static` на корне: `GET /` и всё, что не `/api`, `/ide`,
`/plugin-client` — статика из `engine/apps/web/dist` (путь — `IDE_DIST`
из окружения или `resolve` от пакета `@energy8engine/ide-web`), SPA-fallback
на `index.html` для путей без расширения. Нет `dist` — `GET /` отвечает
страницей с одной диагностикой: «оболочка не собрана: `npm run build -w
@energy8engine/ide-web`» — хост живёт, API работает. `npm run dev` (5680,
прокси на 5679) остаётся путём разработчика IDE; `vite.config.ts` получает
прокси `/api/workspace` вместе с остальным `/api` — ничего нового.

## 8. Клиент

- Плагин `workspace` (`plugins/workspace.ts`): держит `WorkspaceState` с
  провода, `open(id)`, `subscribe`. Источник — `GET /api/workspace` при
  старте и `{ type: 'workspace', workspace }` по ws при каждом
  `workspace/changed`.
- `shell.activity` `workspace` (`order: -1`, первая кнопка, `opens:
  'sidebar'`) и `shell.sidebar` «Проекты»: список `name` (`id` мельче),
  активный отмечен, клик — `open(id)`; пусто — «в этой папке нет проектов»
  + диагностики воркспейса. При старте без активного проекта оболочка
  показывает этот sidebar и пустой документ-группу («откройте проект»).
- Смена проекта в этом браузере: если `shell.hasDirtyDocuments()` —
  подтверждение («несохранённые изменения в N документах будут потеряны»),
  только потом запрос. После `workspace` с другим `active`: все `f:`-
  документы закрываются `close(key, { force: true })`; если среди них были
  грязные (чужое переключение) — одна диагностика `workspace` со списком
  путей. Плагинные документы (`composition`, `preview`) остаются, их
  внутренности перечитывают по снимку/`previewUrl`. `modules` получает
  пустой снимок → отключает клиентские половинки старого проекта (правило
  «строка ушла из снимка» уже есть), потом снимок нового.
- `ProjectStatus`: `name` активного проекта; нет активного — «no project».
- `/#/doc/…` глубокая ссылка без активного проекта: ждёт, как сейчас ждёт
  плагинный документ; «not registered» — после `settled()` при активном
  проекте, иначе «no project open».

## 9. Провод

```
GET  /api/workspace              → WorkspaceState
POST /api/workspace/open {id}    → WorkspaceState | DiagnosticsResponse (400 нет такого id; 500 не поднялся)
POST /api/workspace/close        → WorkspaceState
ws   ServerMessage += { type: 'workspace'; workspace: WorkspaceState }
```

`ServerMessage` расширяется в `@energy8engine/contracts` `protocol.ts`;
`Project`, `WorkspaceState` — там же. Первый кадр по ws после подключения:
`workspace`, затем `snapshot` (пустой, если нет активного).

## 10. Отказ — это данные

- Папка без проектов — состояние, не ошибка; диагностика только если
  `readdir` упал.
- `open(id)` неизвестного id — 400 с диагностикой; `open` того же id —
  no-op, 200.
- Проект не поднялся (плохой `e8.yml`, занят 5681, `e8-server` не стартовал):
  `active` — тот, кто реально стоит (после неудачного `open` — `null`),
  диагностики в ответе и в общем списке; предыдущий проект **не**
  восстанавливается автоматически — это была бы вторая скрытая операция.
- `dist` нет — страница-диагностика, API живо.
- Два `open` подряд — второй ждёт первого (цепочка), не гонка.
- Dispose хоста посреди `open` — `disposed`-флаг, как в `SessionService`.

## 11. Что не входит

Создание проекта из бандла-шаблона (родительская §5 «Новый проект из
бандла-шаблона здесь же» — следующий срез, ему нужен Воркспейс). Удаление
и переименование проектов. Несколько активных игр. Автооткрытие последнего
проекта. Идентичность и права. Песочница хостовых плагинов. HMR оболочки
с хоста.

## 12. Проверка

Юниты (хост): `workspace` — `list` по фикстурной папке (проект / не проект
/ симлинк / файл `e8.yml` не каталог); `name` из `spec.json` и без него;
`open` неизвестного; `open` → scope есть, `open` другого → первый scope
disposed **до** старта второго (порядок по идентичности fiber'ов);
`close`; сериализация двух `open`; `open` при упавшем `project-scope` →
`active: null`, диагностика, порт свободен. `ide-static` — `dist` есть /
нет; SPA-fallback; `/api/*` не перехватывается. `rpc` без `composition` —
пустой снимок.

Юниты (клиент): плагин `workspace` (fetch + ws, `subscribe`); sidebar
«Проекты»; закрытие `f:`-документов при смене `active` с диагностикой о
грязных; `ProjectStatus` с `name`; `PreviewWall` по `previewUrl`/`null`.

Playwright, живой `e8` и настоящий браузер (`workspace.spec.ts`):
1. `e8` в папке с двумя проектами (фикстура: две копии `first-slot`, вторая
   с другим `name`) — sidebar «Проекты» показывает оба имени, ничего не
   открыто, документ-группа говорит «откройте проект»;
2. клик по первому — Проводник показывает его дерево, статус-бар — его
   `name`, превью на `http://127.0.0.1:5681/` спинит (`#status` не пуст);
3. клик по второму — `pgrep e8-server` до/после: один процесс, другой
   pid; превью показывает вторую игру; открытый `.spin` первого закрыт;
4. грязный `.spin` + клик по второму — подтверждение; «Нет» оставляет
   проект и вкладку; «Да» переключает;
5. `e8 dev` в папке проекта (нынешняя фикстура) — проект открыт сразу, все
   существующие 70 тестов проходят без изменения их текста, кроме
   `gameUrl` фикстуры (5681) и `computePreviewUrl`;
6. `GET http://127.0.0.1:5679/` отдаёт оболочку из `dist` (сборка в
   фикстуре один раз), и в ней тот же сценарий 2 проходит без vite 5680;
7. `dist` убран — `GET /` отдаёт страницу с диагностикой, `/api/workspace`
   — 200.

Каждое утверждение — с мутацией, которая обязана его уронить, и счётчиком
до/после на оригинале. Playwright — один, без других корневых npm-команд;
`pgrep -fl e8-server` до и после; порты 5679/5680/5681.

## 13. Риски

| Риск | Вес | Что делаем |
|---|---|---|
| `plugin-include` не примет абсолютный путь / entry не снимется со scope | высокий | Спайк — задача 1 плана; два запасных пути названы в §5 |
| Второй `plugin-server` в одном процессе делит глобальное состояние (`ctx.server` — сервис по имени) | высокий | В `dev-game` второй сервер живёт под своим именем (`previewServer`) через `ctx.plugin(Server, …)` в изолированном child-ctx или с переименованием сервиса; измеряется тем же спайком |
| `e8-server` осиротеет при быстром переключении | средний | `open` сериализован; `close` ждёт `session` dispose; тест 3 считает pid |
| 70 e2e-тестов завяжутся на порт 5681 | средний | Фикстура `startDevHost` меняется в одном месте; `gameUrl` — с провода |
| Сборка `dist` в e2e удлинит прогон | низкий | Собирается один раз в `globalSetup`, тест 6–7 — два теста |
| `ctx.baseUrl` корня больше не проект — что-то ещё резолвит относительно него | средний | `grep baseUrl` — сегодня один пользователь (`index.ts:61`); `composition.ts` резолвит пакеты от `config.cwd` |
